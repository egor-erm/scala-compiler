# Где в парсере употребляются `nl` и `nlnl` (Scala 2.13)

Источник: спецификация Scala 2.13, раздел 1.2 «Newline Characters» и грамматика (глава 13),
а также `Scanners`/`Parsers` из scalac. `nl` — один или несколько переводов строки без пустой
строки, `nlnl` — перевод строки с пустой строкой (две и более `\n`).

Лексер выдаёт токен только если выполнены три условия (предыдущий токен может завершать
оператор, следующий — начинать, область допускает переводы строк). Всё ниже — места, где
парсер **принимает** уже выданный токен.

## 1. Разделитель операторов (`semi`)

В грамматике `semi ::= ';' | nl {nl}` — `nl` и `nlnl` оба работают как `;`, где разрешён `;`:

| Контекст | Пример |
|---|---|
| Операторы верхнего уровня файла (`TopStatSeq`) | `import a.b` ⏎ `object X` |
| Операторы в `package p { ... }` | |
| Тело класса / трейта / объекта (`TemplateStat`) | `val a = 1` ⏎ `def f = 2` |
| Блок `{ ... }` (`BlockStat`) | `{ val x = 1` ⏎ `x + 1 }` |
| Тело ветки `case p => ...` (до следующего `case` или `}`) | `case 1 =>` ⏎ `a` ⏎ `b` |
| Тело лямбды `x => ...` внутри блока | `{ x =>` ⏎ `x + 1 }` |
| Список `import`-ов и `package`-ов в начале файла | |

Во всех этих местах `nl` и `nlnl` равнозначны: `a` ⏎ `b` и `a` ⏎ ⏎ `b` — два оператора.

## 2. Только `nlnl` допустим (`nl nl` — «множественный перевод строки»)

Спецификация: «Multiple newline tokens are accepted in the following places (a semicolon in
place of the newline would be illegal in every one of these cases)»:

1. Между условием `if (...)` / `while (...)` и следующим выражением:
   ```scala
   if (x > 0)

     println(x)
   ```
2. Между генераторами `for (...)` / `for {...}` и телом (после `yield` или без него):
   ```scala
   for (i <- 1 to 3)

     println(i)
   ```
3. После ключевого слова `type` в определении/объявлении типа:
   ```scala
   type

     T = Int
   ```

Одиночный `nl` в этих местах лексер не выдаёт вовсе (после `)` и перед выражением в круглых
скобках область отключена), поэтому на практике парсер видит здесь именно `nlnl` либо
ничего. Но в грамматике они записаны как `{nl}`, поэтому правило должно принимать
`nl` и `nlnl`.

## 3. Только одиночный `nl` (необязательный, `[nl]`)

«A single new line token is accepted»:

1. **Перед открывающей `{`**, если она — допустимое продолжение:
   ```scala
   def f(x: Int)
   {
     x
   }
   class A extends B
   {
     ...
   }
   ```
2. **После инфиксного оператора**, если следующая строка начинает выражение:
   ```scala
   val a = 1 +
     2
   ```
   (`+` — идентификатор, лексер выдаёт `nl`, парсер его пропускает.)
3. **Перед списком параметров**:
   ```scala
   def f(a: Int)
        (b: Int) = a + b
   class P(x: Int)
          (y: Int)
   ```
4. **После аннотации**:
   ```scala
   @deprecated
   def old() = 1
   ```

В грамматике: `[nl]` в местах `newLineOptWhenFollowing` и `newLineOpt` в `Parsers.scala`.

## 4. Где `nl`/`nlnl` НЕ появятся (лексер их не выдаёт)

| Ситуация | Причина |
|---|---|
| Перед `else`, `catch`, `finally`, `extends`, `with`, `match`, `yield`, `forSome` | эти слова не могут начинать оператор |
| Перед `.`, `,`, `)`, `]`, `}`, `;`, `[` | не могут начинать оператор |
| После `=`, `=>`, `<-`, `<:`, `>:`, `<%`, `:`, `#`, `@`, `val`, `var`, `def`, `class`, `if`, `while`... | не могут завершать оператор |
| Внутри `( ... )` и `[ ... ]` | область, где переводы строк отключены |
| Между `case` и `=>` (шаблон ветки) | область `=>` |
| `; else` | `;` перед `else` отбрасывается |

## 5. Рекомендация для грамматики (bison)

```yacc
semi    : ';' | NL | NLNL ;                 /* разделитель операторов */
nls     : /* empty */ | NL | NLNL ;         /* любое число переводов строк */
nl_opt  : /* empty */ | NL ;                /* строго одиночный */

/* 1 */  stat_seq : stat | stat_seq semi stat ;          /* + пустые semi по необходимости */
/* 2 */  if_expr  : IF '(' expr ')' nls expr ... ;
         while    : WHILE '(' expr ')' nls expr ;
         for      : FOR '(' enums ')' nls expr ;
         type_def : TYPE nls id ... ;
/* 3 */  block_brace : nl_opt '{' ... '}' ;   /* перед { */
         infix_expr  : expr op nl_opt expr ;  /* после инфиксного оператора */
         param_clauses : '(' ... ')' nl_opt '(' ... ')' ;
         annotated    : annotation nl_opt def ;
```

Если разбор различий `nl`/`nlnl` пока не нужен, достаточно `semi: ';' | NL | NLNL` и `nls`
вместо `nl_opt` везде; различие `nl` и `nlnl` нужно только в пункте 2.

if_expr : IF '(' expr ')' nls expr
        | IF '(' expr ')' nls expr opt_semi ELSE nls expr ;
opt_semi : /* empty */ | ';' ;


Ситуация:
a +/* c */ b

до: 
id: a, id: +/*, id: c, id: */, id: b

после:
id: a, id: +, id: b
