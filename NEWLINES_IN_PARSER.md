# Обработка переводов строк в лексере и парсере

Документ описывает принятую в проекте модель для подмножества Scala 2.13. За основу взяты
раздел 1.2 «Newline Characters» и грамматика Scala 2.13, но внутреннее представление упрощено:
используется только токен `NL`, отдельного токена `NLNL` нет.

## 1. Представление переводов строк

Лексер выдаёт `NL`, только если одновременно выполнены условия:

1. предыдущий токен может завершать оператор;
2. следующий токен может начинать оператор;
3. текущая область допускает переводы строк.

Если условия выполнены, каждый обнаруженный перевод строки выдаётся отдельным `NL` без
ограничения их количества:

```text
один перевод строки  -> NL
два перевода строки  -> NL NL
три перевода строки  -> NL NL NL
```

Если условия не выполнены, переводы строк пропускаются, как и раньше.

## 2. Разделители операторов

Одиночный `NL` работает как `;`. Последовательности разделителей принимаются через `semis`:

```yacc
semi:
    ';'
  | NL
  ;

semis:
    semi
  | semis semi
  ;

semis_e:
    /* empty */
  | semis
  ;
```

Это используется:

- между объявлениями верхнего уровня;
- между инструкциями тела класса или объекта;
- между инструкциями блока `{ ... }`;
- между выражениями тела ветки `case`;
- между генераторами `for` в фигурных скобках.

Например:

```scala
case 1 =>
  a
  b
case 2 =>
  c
```

Переводы строки между `a`, `b` и следующим `case` обрабатываются через `block_stats` и `semis`.
Дополнительное `nls` после `=>` не требуется: после `=>` лексер не выдаёт `NL`, поскольку этот
оператор не может завершать оператор.

В `do ... while` используется `semis_e`, поэтому между телом и `while` допускается несколько
переводов строки:

```yacc
do_while_expr:
    DO expr semis_e WHILE '(' expr ')'
  ;
```

## 3. Произвольное количество `NL`

Рекурсивный `nls` принимает любое число переводов строки:

```yacc
nls:
    /* empty */
  | nls NL
  ;
```

Он используется между условием или генераторами и телом выражения:

```yacc
if_expr:
    IF '(' expr ')' nls expr
  | IF '(' expr ')' nls expr ELSE expr
  ;

while_expr:
    WHILE '(' expr ')' nls expr
  ;

for_expr:
    FOR '(' generator_list ')' nls expr
  | FOR '{' semis_e generator_list semis_e '}' nls expr
  ;
```

Например:

```scala
if (x > 0)


  println(x)
```

Произвольное количество `NL` также принимается перед параметрами и телом класса. Это необходимо,
в частности, для `class Test` с пустой строкой перед `{` из `lexer/hard_test.scala`:

```yacc
class_fields:
    nls '(' ')'
  | nls '(' field_list ')'
  ;

class_body:
    nls '{' stmt_list_e '}'
  ;
```

`nls` используется в обоих правилах одновременно: сочетание `class_fields.nl_e` и
`class_body.nls` создаёт shift/reduce-конфликт на первом `NL` после имени класса.

Если позднее будут добавлены определения типов, после ключевого слова `type` также следует
использовать `nls`.

## 4. Не более одного `NL`

Необязательный одиночный перевод строки представлен через `nl_e`:

```yacc
nl_e:
    /* empty */
  | NL
  ;
```

Он применяется в местах, где грамматика Scala использует `[nl]`:

1. После инфиксного оператора:

   ```scala
   val a = 1 +
     2
   ```

2. Перед списком параметров метода:

   ```scala
   def f
     (x: Int): Int = x
   ```

В текущей грамматике это выражено через `params_e`, правила инфиксных операторов и составных
присваиваний. Заголовок класса использует более permissive `nls`, как описано выше.

В позициях, использующих `nl_e`, несколько переводов строки поступают как `NL NL` и не
принимаются. Произвольное количество переводов строки разрешено только через `nls` и `semis`.

## 5. Где `NL` не появляется

Лексер не выдаёт `NL`:

- перед `else`, `catch`, `finally`, `extends`, `with`, `match`, `yield`, `forSome`;
- перед `.`, `,`, `)`, `]`, `}`, `;`, `[`;
- после `=`, `=>`, `<-`, `<:`, `>:`, `<%`, `:`, `#`, `@`;
- после ключевых слов, которые не могут завершать оператор, включая `val`, `var`, `def`, `class`;
- внутри `( ... )` и `[ ... ]`;
- между `case` и соответствующим `=>`, пока активна область `=>`.

Поэтому в этих местах дополнительные правила для пропуска `NL` не нужны.
